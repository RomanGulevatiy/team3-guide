# 2. Налаштування File Header

Щоб у кожному файлі автоматично з'являвся ваш підпис - пропоную налаштувати шаблон один раз.

### Кроки:

1. Двічі натисніть `Shift` -> відкриється пошук
2. Введіть `File and Code Templates` -> оберіть його зі списку
3. Перейдіть у вкладку **`Includes`**
4. Оберіть **`File Header`**
5. Вставте текст нижче (замінивши дані на свої)

> [!TIP]
> Дані вкажіть **англійською**, спочатку ім'я, потім прізвище.\
> змінна `${DATE}` - встановлює поточний час

```java
/**
 * Created by Ім'я Прізвище on ${DATE}.
 * github github.com/ваш-username
 */
```

# 3. Основи Git та GitHub 

## 3.1. Що таке Git?

**Git** - це система, яка зберігає всю історію змін у коді. Уявіть, що кожен ваш `commit` - це збереження в грі: ви завжди можете повернутися до будь-якої точки.

**GitHub** - це сайт, де зберігається спільний код нашої команди (хмара для Git).

> Раджу переглянути відео для кращого розуміння -> [Git и GitHub для новичков](https://youtu.be/EeARyFrZsnU?si=0tKs882tJo4s9Qkr)

---

## 3.2. Підключення GitHub акаунту в IntelliJ IDEA

Після встановлення IntelliJ IDEA треба увійти в свій GitHub - це робиться один раз.

### Кроки:

1. Відкрийте File -> Settings (або `Ctrl + Alt + S`)
2. Перейдіть в `Version Control -> GitHub`
3. Натисніть `+` (додати акаунт) -> оберіть `Log In with Token`
4. У новому вікні натисніть сіру кнопку `Generate`
5. Відкриється браузер - оберіть усі чекбокси і згенеруйте токен
6. Вставте токен в поле `Token:   ` всередині IntelliJ -> `Add account`

![GitHub token](https://github.com/RomanGulevatiy/team3-guide/blob/main/images/github-token.png)

## 3.3. Клонування репозиторію

**Клонування** - це завантаження проєкту з GitHub на ваш комп'ютер.

**Один раз на початку роботи:**

1. Перейдіть на сторінку [репозиторію](https://github.com/Java-Spring-Sprint-Class/teamwork-management-system-team-3) на GitHub
2. Натисніть зелену кнопку **`<> Code`**
3. Скопіюйте посилання (HTTPS)
4. Відкрийте IntelliJ IDEA -> `File -> New -> Project from Version Control`
5. Вставте посилання -> натисніть **Clone**

## 3.4. Гілки (branches)

**Гілка** - це ваш особистий "рядок" змін, ізольований від основного коду. Це потрібно щоб ваші незакінчені зміни не ламали проєкт для інших.

> [!CAUTION]
> **Головне правило:** Ми ніколи не пишемо код напряму в гілці `main`!

```
main ──●──────────────────────────────────●── (стабільний код)
        \                                /
         ●────● sprint-1/feature/my-task (ваша гілка)
```

### Як створити нову гілку

> [!WARNING]
> Завжди створюємо НОВУ гілку від актуального `main`!

```bash
# Крок 0: перевірте свою поточну гілку
git status

# Крок 1: перейдіть на main (якщо до цього перебували в іншій гілці)
git checkout main

# Крок 2: завантажте останні зміни
git pull

# Крок 3: створіть нову гілку і одразу перейдіть на неї
git checkout -b sprint-номер/feature/назва-вашої-задачі
```

### Правила неймінгу гілок

> Перед типом задачі рекомендується вказувати поточний спринт `sprint-n/`.\
> Назва англійською, слова через `-`, коротко але зрозуміло.

| Тип задачі | Префікс | Приклад |
|---|---|---|
| Нова функціональність | `feature/` | `feature/user-registration` |
| Виправлення помилки | `fix/` | `fix/login-null-pointer` |
| Рефакторинг | `refactor/` | `refactor/user-service` |

![Branch switching](https://github.com/RomanGulevatiy/team3-guide/blob/main/images/branch-switching.gif)

## 3.5. Щоденний цикл роботи

**Кроки 1-3:** 1. Оновити `main` -> 2. Створити гілку -> 3. Писати код

**Крок 4 - зробити commit (зберегти зміни локально):**

```bash
# Подивитися які файли змінились
git status

# Додати всі змінені файли
git add .

# Або додати конкретний файл
git add src/main/java/com/example/UserService.java

# Зробити commit
git commit -m "feat: add user registration logic"
```

**Крок 5 - запушити (відправити на GitHub):**

```bash
git push origin sprint-номер/feature/назва-твоєї-гілки
```

**Крок 6:** відкрити Pull Request ([перейти до розділу нижче](#37-pull-request-pr))

## 3.6. Стиль комітів (Commit Naming)

> [!IMPORTANT]
> Назва коміту - це не "зміни", "правки" або "asdfgh". Коміт має чітко говорити **ЩО** було зроблено.

Формат:
```
тип: короткий опис що зроблено (англійською)
```

### Типи комітів, які вам необхідно знати:

| Тип | Коли використовувати | Приклад |
|---|---|---|
| `feat` | Нова функціональність | `feat: add email validation` |
| `fix` | Виправлення помилки | `fix: null pointer in UserService` |
| `refactor` | Рефакторинг без зміни логіки | `refactor: extract validation to separate method` |

### Правила:
- Бажано **Англійська мова**
- Нижній регістр після двокрапки
- Коротко (до 72 символів)
- Теперішній час: `add`, `fix`, `update` (не `added`, `fixed`)

## 3.7. Pull Request (PR)

**Pull Request** - це запит на злиття твоєї гілки в `main`. При створенні PR ви обираєте члена команди, який перевіряє код і дає зворотний зв'язок перед тим як код потрапить у спільний проєкт.

### Як відкрити PR:

1. Запушили гілку -> на сайті GitHub покаже жовтий банер **"Compare & pull request"** - натисніть його
2. Або: вкладка **`Pull requests`** -> **`New pull request`**
3. Заповніть:
   - **Назва:** коротко що зроблено (`feat: add user registration`)
   - **Опис:** що зроблено, що перевірити, чи є нюанси
   - **Reviewers:** додайте члена команди
4. Натисніть **`Create pull request`**

> [!WARNING]
> Не мержіть PR самостійно! Тільки після approve від переглядача.

### Що робити якщо переглядач залишив коментар до PR?

1. Читаєте коментар
2. Вносите зміни в той самий код (на тій самій гілці)
3. Робите новий `commit` і `push` - він автоматично додасться до вже відкритого PR
4. Відповідаєте на коментар або натискаєте **"Resolve conversation"**
